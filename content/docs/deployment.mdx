---
title: Documentation Deployment
description: How the static documentation site is built and published to GitHub Pages.
---

The documentation site uses Next.js static export and Fumadocs MDX. It has no backend, database, authentication, API routes, model calls, or publishing integration.

## Local build

```bash
npm ci
npm run typecheck
npm run build
```

The build creates `out/`, a static directory that can be served by any ordinary web server. It is ignored by Git.

## GitHub Pages workflow

`.github/workflows/deploy-docs.yml` runs on pushes to `main` and manual dispatches. It installs exactly the `package-lock.json` dependencies, type-checks, builds with the repository base path, uploads `out/`, and uses the official GitHub Pages deployment action.

The workflow does not invoke the runtime, call a model, read local source repositories, generate documentation, or write back to Git.

## One-time GitHub setting

After the workflow is pushed, enable GitHub Pages in the repository settings and select **GitHub Actions** as the source. GitHub then reports the deployed URL in the workflow environment. The expected project-site URL is:

```text
https://omidakhavans.github.io/personal-ai-agent/
```

## Public-data check

Before deployment, review the diff for real API keys, local machine paths, generated run state, research artifacts, usernames, internal URLs, and customer data. This site is intentionally sourced from reviewed MDX files and uses placeholders for local paths and credentials.
