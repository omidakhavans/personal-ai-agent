This site explains the Phase 2 implementation of the Personal Applied AI Engineering project.

The repository is a small Python runtime that makes the mechanics behind an AI workflow visible:

- a command-line entry point;
- persistent run state and Markdown artifacts;
- grounded repository and resource research;
- evidence reduction before later generation;
- explicit `completed`, `blocked`, and `failed` outcomes;
- human review before publishing.

The current real stages are:

```text
research-work -> research-resources -> build-evidence-context -> write-blog
```

The review and social stages remain placeholders. That is intentional: the learning focus is currently on grounding, context engineering, grounded generation, and runtime reliability rather than publishing automatically.

## Public documentation boundary

This site intentionally contains no local machine paths, generated run artifacts, credentials, or research output. Examples use placeholders. The runtime itself keeps local resume locations outside shareable state and artifacts.

Public source code is different: this documentation may cite repository-relative paths, classes, functions, small explanatory excerpts, and exact line links to this public GitHub repository. When a guide explains a specific implementation, it should prefer a commit-pinned GitHub permalink so the cited lines stay stable. Source references are useful learning evidence; private machine data is not.
